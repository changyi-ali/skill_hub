# Dash Dev Server Remote

处理用户针对 `dash-dev-server` 的三个快捷口令。把口令视为对对应动作的明确授权，但仍服从运行环境的文件权限和审批机制。

## “远程 <IP>”

当用户给出类似“远程 10.72.2.181”的指令时：

1. 验证参数是合法的 IPv4 或 IPv6 地址；不要接受命令片段、URL、端口或主机配置文本作为 IP。
2. 读取 `~/.ssh/config`，精确定位 `Host dash-dev-server` 配置块。配置块从该 `Host` 行开始，到下一个 `Host` 或文件结尾为止。
3. 确认该配置块恰好存在一次，且其中的 `HostName` 可唯一确定。若目标块缺失、重复，或 `HostName` 重复，不猜测、不修改，向用户报告。
4. 仅把目标块中的 `HostName` 值替换为用户给出的 IP。保留 `User`、`Port`、`ProxyJump`、`IdentityFile`、注释、缩进以及其他 Host 配置不变。
5. 修改后执行 `ssh -G dash-dev-server`，核验解析出的 `hostname` 等于新 IP，并向用户报告结果。若解析不一致，停止连接并说明问题。

不要把某个 IP 固化为默认值。不要因为更新目标地址而修改跳板机配置。

## “服务器脚本”

当用户只说“服务器脚本”时：

1. 读取 `~/code/scripts/spectrum_remote.sh` 的完整内容。
2. 只读取和返回，不执行、不修改脚本。
3. 输出前检查密码、访问令牌、私钥和其他秘密。SSH 公钥本身不属于秘密；秘密值应脱敏，并明确说明发生了脱敏。
4. 文件不存在或不可读时，返回实际路径和错误，不用其他同名文件代替。

## “远程连接”

当用户说“远程连接”时：

1. 查看当前任务是否已有仍然可用的 `dash-dev-server` SSH 会话；可安全复用时优先复用。
2. 否则执行交互式 `ssh dash-dev-server`，保留会话以供后续远程操作使用。
3. 成功进入后，通过远端命令核验当前用户、hostname 和连接所对应的 IP，并报告这些信息。不要只凭 SSH 命令没有报错就宣称连接成功。
4. 连接失败时保留完整的关键错误类型，并区分 DNS/配置解析、跳板机、超时、主机密钥和认证失败；不要未经用户要求改动其他 SSH 设置来绕过错误。

## 操作边界

- 用户单独说“远程连接”不代表允许修改 IP；用户单独说“远程 <IP>”也不自动代表需要建立连接，除非用户同时提出连接要求。
- 不关闭或破坏仍可能被用户使用的其他 SSH 会话。
- 涉及工作区外文件时，按环境要求申请写权限。权限未获批准时，报告阻塞，不用复制配置或更改其他文件来规避限制。
- 所有成功结论都应基于动作完成后的可观察验证结果。
