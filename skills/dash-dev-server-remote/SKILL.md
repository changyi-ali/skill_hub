# Dash Dev Server Remote

处理用户针对 `dash-dev-server` 的三个快捷口令。把口令视为对对应动作的明确授权，但仍服从运行环境的文件权限和审批机制。

## “远程”或“远程 <IP>”

当用户只说“远程”且未提供 IP 时，直接提示用户补充 IP，不读取或修改文件。

当用户给出类似“远程 10.72.2.181”的指令时，直接编辑 `~/.ssh/config`：定位 `Host dash-dev-server` 配置块，只把该配置块中的 `HostName` 值替换为用户提供的内容，保留其他配置不变。不要额外校验 IP 格式，不要在修改前后执行 `ssh -G`、回读比较或其他验证操作。编辑命令失败时返回实际错误。

不要把某个 IP 固化为默认值。不要因为更新目标地址而修改跳板机配置。

## “服务器脚本”

当用户只说“服务器脚本”时：

1. 直接执行 `cat ~/code/scripts/spectrum_remote.sh`。
2. 原样返回 `cat` 的标准输出，不扫描、不脱敏、不解释，也不执行或修改脚本。
3. `cat` 失败时原样返回实际错误，不查找其他同名文件，也不做额外操作。

## “远程连接”

当用户说“远程连接”时：

1. 查看当前任务是否已有仍然可用的 `dash-dev-server` SSH 会话；可安全复用时优先复用。
2. 否则执行交互式 `ssh dash-dev-server`，保留会话以供后续远程操作使用。
3. 成功进入后，通过远端命令核验当前用户、hostname 和连接所对应的 IP，并报告这些信息。不要只凭 SSH 命令没有报错就宣称连接成功。
4. 连接失败时保留完整的关键错误类型，并区分 DNS/配置解析、跳板机、超时、主机密钥和认证失败；不要未经用户要求改动其他 SSH 设置来绕过错误。

## 操作边界

- 用户单独说“远程连接”不代表允许修改 IP；用户说“远程 <IP>”也不自动代表需要建立连接，除非用户同时提出连接要求。
- 不关闭或破坏仍可能被用户使用的其他 SSH 会话。
- 涉及工作区外文件时，按环境要求申请写权限。权限未获批准时，报告阻塞，不用复制配置或更改其他文件来规避限制。
- “远程 <IP>”和“服务器脚本”分支不追加用户未要求的校验、解释或后续动作。
